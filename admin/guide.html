1. 核心原則

Admin 內的操作先是本機草稿。只有建立 GitHub Issue 並由自動流程成功套用後，正式網站資料才會改變。
  • 草稿保存在目前瀏覽器。
  • 送出前先檢查右側預覽。
  • 頁面、類別與項目共用同一份資料，網站與兩份 PDF 履歷會一起更新。

2. 項目清單

每筆資料上方顯示「項目類型、所在頁面、所在類別」三組提示標籤；頁面項目改顯示語言版本。搜尋、篩選項目類型或切換檢視排序時，標籤會保持新版樣式。

「網站順序」反映正式資料加本機草稿後的位置；日期與名稱排序只改變 Admin 的查看順序，不會修改網站。

3. 一般內容與六種顯示風格

新增和編輯一般內容時都能改「顯示風格」。選擇後，「所屬類別」只列出能接受該風格的類別；若目前沒有相容類別，儲存按鈕會停用。

4. 統一排序與搬移

  • 選擇頁面後，可調整類別順序與類別內項目順序。
  • 每個項目都有「搬移」選單，列出所有使用相同格式、可安全接收的類別。
  • 沒有相容類別時，選單會保留但呈灰色停用。
  • 搬移可以跨頁面；項目會跟隨目標類別。
  • PDF 履歷檢視只調整履歷類別順序，因此搬移選單停用。

5. 首頁精選與近期活動

這組功能位於「排序」下方的摺疊區。精選論文可選最新 N 篇、最舊 N 篇或手動清單；近期活動可選最近 N 筆、日期最遠 N 筆或手動清單。

每次選擇都會立即保存，區塊上方會顯示是否有未送出變更。首頁草稿也會出現在「草稿」分頁，可修改、預覽或移除。這裡只控制首頁雙欄，不會刪除原始論文或活動。

6. 草稿與預覽

  • 新增、修改、刪除、頁面／類別、排序與首頁設定都會列入草稿。
  • 按「預覽」查看單筆修改前後；新增與修改草稿可再次編輯。
  • 「清空內容草稿」會移除內容、排序、首頁與還原草稿，但不會修改正式網站。

7. 頁面與類別

頁面與類別從「新增」建立，也會出現在「項目」清單。頁面可選雙語、僅中文或僅英文；類別可編輯中英文標題、簡介、所在頁面，以及網站／PDF 顯示狀態。

類別顯示風格建立後固定。需要另一種排版時，新增相應風格類別，再透過項目編輯或排序中的「搬移」轉移項目。

8. GitHub 送出

  1. 檢查草稿與右側總預覽。
  2. 按「前往 GitHub 送出批次」。
  3. 確認 Issue 已建立且自動流程完成。
  4. 回到 Admin 按「已建立 GitHub Issue：清空本機草稿」。

9. 疑難排解

狀況處理
搜尋、篩選或排序後標籤變舊重新整理一次以載入最新版；新版會固定使用同一個項目渲染入口。
搬移選單是灰色目前沒有其他能接受相同格式的類別；先新增相同顯示風格的類別。
首頁選擇後看似沒有保存檢查區塊上方是否顯示「有未送出變更」，並到「草稿」確認首頁設定。
改風格後出現刪除與新增兩筆草稿這是榮譽與其他一般內容之間的安全轉換，屬正常行為。
