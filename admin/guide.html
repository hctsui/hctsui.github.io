1. 標準工作流程

Admin 的修改不會立即寫入 GitHub。所有操作先存成目前瀏覽器的本機草稿。
  1. 在「項目」「新增」「排序」「資料庫」或「網站設定」建立修改。
  2. 在「草稿」與右側預覽檢查差異。
  3. 按「前往 GitHub 送出批次」建立 Issue。
  4. 確認 GitHub Actions 成功、Issue 自動關閉並完成部署。
  5. 最後才清空已送出的本機草稿。

同一批次可包含內容、頁面與類別、排序、首頁、中英對照、人名連結、個人資料、通知狀態與網站設定。

2. Admin 介面總覽

入口用途
項目搜尋、篩選、查看、編輯或刪除頁面、類別與內容。
新增新增頁面、類別、作品、活動、教學與一般內容；活動內再選擇四種實際類型。
排序調整一般頁面、首頁、個人資料、PDF 履歷與審查資料。
還原查看並還原最近 7 天的正式操作。
草稿查看、修改、預覽或移除未送出的操作。
資料庫管理中英對照、標籤、人名連結與姓名一致性。
網站設定管理個人資料、封面、導覽列、頁尾、404、聯絡表單、SEO／OG 與流量統計。
通知查看部署、arXiv、正式出版、失效連結與聯絡留言。

左側是操作區；右側顯示目前編輯預覽、整批差異、批次 JSON 與送出按鈕。

3. 項目清單

清單包含頁面、類別與內容項目。可依網站順序、日期或名稱查看；檢視排序本身不會改變網站。

  • 頁面標籤會顯示主要所在頁面與所有引用頁面。
  • 頁面不能當成一般內容直接刪除。
  • 類別必須先移走所有主要項目與引用才能刪除。
特殊跳轉：在項目清單點「個人資料」的編輯，會前往個人資料表單；點「PDF 履歷」的編輯，會前往 PDF 履歷排序。

4. 新增、編輯與自動填寫

  • 中英文：分開儲存；自動填寫先查人名連結，再查中英對照。
  • 精確比對：找不到相同詞條時，不會自行翻譯或直接複製。
  • 日期：可輸入 YYYY/MM/DD 或使用日曆；結束日期留白時使用開始日期。
  • 主要類別：決定管理位置與預設顯示位置。
  • 額外顯示位置：可把同一筆資料引用到其他相容類別。
  • 網址：可用完整 http／https 網址或網站內根目錄相對路徑。
自動填寫不是 AI 翻譯。資料庫沒有匹配時，另一語言會保持空白。

5. 各資料類型

作品／論文題目、逐位作者、日期、作品類別、期刊或 arXiv、PDF、DOI、程式碼、BibTeX 與 bibitem。
學術會議會議名稱、身分、日期、場地、城市、國家與連結。
學術報告題目、活動、日期、機構、地點、活動連結與投影片。
學術訪問訪問機構、日期、地點、資助與說明。
學術籌辦會議、工作坊、研討會或讀書會，以及主辦、協辦或召集身分。
教學機構、身分、課號、課名、學期與講義。
榮譽獎項、獎助與榮譽紀錄。
一般內容學歷、任職、研究方向、技能、聯絡資訊與其他自訂內容。

目前的活動新增流程

「新增」中的活動入口統一為「活動」。進入後再選擇學術會議、學術報告、學術訪問或學術籌辦；表單上方可返回活動類型選擇。項目清單與類型篩選仍以四種實際類型分開顯示。

6. 一般內容顯示風格

顯示風格只控制版面，不限制用途。新增與編輯一般內容時都可選擇；「一般內容（不限風格）」允許每筆項目保留自己的風格。

標準時間軸一般經歷、職務與活動。
雙欄紀錄學歷或任職紀錄。
標題清單研究興趣與簡短主題。
資訊卡片聯絡方式與重點資訊。
標籤列表語言、技能與個人資訊。
精簡時間軸榮譽與短紀錄。

已有主要項目或引用的類別會鎖定風格；必須先移走內容才能修改。

7. 頁面與類別

公開頁面可設定中英文名稱、頁首文字、主色、語言版本、導覽列顯示與順序。類別決定頁面區塊的標題、簡介與排版。

特殊頁面用途
個人資料集中保存個人資料主項目，不生成公開 HTML。
PDF 履歷保存 PDF 履歷專用類別與引用，不生成公開 HTML。
審查資料依納入設定與排序生成中英文公開頁面，預設不放入導覽列。

「納入 PDF 履歷／審查資料」與「排序」是兩件事：先納入，再安排位置。

8. 主要類別與引用位置

一份資料→主要類別＋其他類別引用
  • 修改主資料一次，所有引用同步更新。
  • 每個顯示位置有自己的排序。
  • 移除引用不會刪除主資料。
  • 移動主要類別不會自動移除其他引用。
  • 只有顯示風格相容的類別可互相移動或引用。

9. 個人資料編輯

網站設定→一般設定→個人資料編輯

可集中管理姓名、所屬單位、職位、學校信箱、個人信箱、網站、ORCID、地址、辦公室與語言。

  • 姓名、所屬單位與職位會顯示在審查資料的個人資料區塊。
  • 聯絡區塊不重複顯示上述資料。
  • 首頁、PDF 履歷與其他頁面使用引用。

10. 排序系統

在「排序」選擇一般頁面或特殊輸出，可調整類別、主要項目與引用的順序。

  • 一般頁面：調整公開網站內容。
  • 個人資料：調整主項目管理順序。
  • PDF 履歷：調整 PDF 類別與引用。
  • 審查資料：調整審查資料類別與項目。

快速排序可依日期或名稱排列；作品與教學保留原分組，只在組內排序。

11. 首頁精選論文與近期活動

在「排序」選擇首頁時，精選論文與近期活動會直接出現在首頁的排序內容中，不再使用舊的獨立收合面板。

精選論文固定最新 N 篇、固定最舊 N 篇、手動選擇與排序。
近期活動最近即將開始的 N 筆、日期最遠的 N 筆、手動選擇與排序。

近期活動只列出尚未結束的活動；過期後從首頁隱藏，但原始資料仍保留。

12. PDF 履歷

  • 類別需先設定「放進 PDF 履歷」。
  • 中英文 PDF 共用類別與項目順序。
  • 預印本、期刊論文與綜述論文各自編號。
  • 教學可依機構與身分整理。
  • 空類別不輸出。
  • 在項目清單點「PDF 履歷」的編輯會直接跳到排序。

13. 審查資料

類別需勾選「放進審查資料」，再到「排序 → 審查資料」安排順序。

  • 個人資料區塊固定顯示姓名、所屬單位與職位。
  • 聯絡區塊排除上述三項，避免重複。
  • 其他內容依類別設定與排序生成。
  • 螢幕使用雙欄版面；列印使用可跨頁的雙欄內容流。
  • 列印採 A4、黑白，隱藏導覽列、頁尾與連結按鈕。

14. 中英對照資料庫

只做完整欄位精確比對，不做模糊翻譯。

  • 多標籤篩選採全部符合。
  • 標籤可新增、改名、合併、刪除與排序。
  • 安全合併會保留匯入檔未列出的既有資料。
  • 完整取代前必須檢查完整差異。
  • 匯入後仍是本機草稿，需走一般送出流程。

15. 人名連結資料庫

管理英文姓名、中文姓名、學術網頁與其他拼法。其他拼法只供搜尋、作者候選與精確比對，不改變網站顯示。

姓名類型自動處理
華人羅馬字姓名連字號、空格、合併、姓前名後與逗號格式。
外國姓名中間名、縮寫、姓名順序與逗號格式。

作者欄輸入文字時只顯示候選，必須手動點選才會套用標準姓名。系統也會檢查既有論文作者，可單筆或全部更改。

直接開啟人名：若正式檔案尚未載入完成，Admin 會等待並重試；遇到部署交界的舊快取時最多安全重新載入一次，再自動開啟原本指定的人名。

16. 網站設定

  • 一般設定：個人資料、封面、導覽列、頁尾與 404。
  • 聯絡表單：Web3Forms Email-Only 或 Cloudflare Worker 橋接模式，以及 Cloudflare Turnstile。
  • SEO／OG：基準網址、網站名稱、分享圖片、各頁標題與描述。
  • 流量統計：Cloudflare Web Analytics 或 Google Analytics 4。

17. 通知中心

  • arXiv 新論文可加入草稿、忽略、加星號或標記已讀。
  • 正式出版可將預印本轉為期刊論文草稿。
  • 失效連結可跳到對應項目或設定。
  • 聯絡留言可開啟電子郵件收件匣並標記已處理。
  • 部署狀態可開啟 GitHub Actions 執行紀錄。

18. 草稿、預覽與批次 JSON

  • 修改草稿：返回對應表單。
  • 預覽：查看單筆修改前後差異。
  • 移除：只移除該草稿，不影響正式資料。
  • 清空內容草稿：清除一般內容、排序、首頁與還原草稿；中英對照、人名連結、個人資料及網站設定各自有獨立的放棄修改按鈕。

技術資料中的 JSON 是實際送到 GitHub Issue 的內容，通常不需手動編輯。

19. GitHub 送出與部署

  1. 確認右側沒有不能送出的錯誤或意外大量變更。
  2. 按「前往 GitHub 送出批次」。
  3. 依畫面建立以 [Website: Batch] 開頭的 Issue。
  4. GitHub Actions 執行測試、套用資料並生成網站、審查資料、PDF 履歷與搜尋索引。
  5. 成功後 Issue 自動關閉並部署 GitHub Pages。
Issue 剛建立時不要清空草稿。先確認 GitHub Actions 成功。

20. 還原與最近操作

保留最近 7 天的正式操作，可搜尋、預覽、查看 JSON 並建立單筆還原草稿。若資料之後又被修改，系統會阻止舊版本覆蓋新內容。

21. 自動產生與同步

網站頁面依頁面、類別、主要項目與引用生成中英文 HTML。
PDF 履歷生成中英文 LaTeX 與 PDF。
審查資料生成中英文頁面與列印版。
首頁活動過期後停止顯示，不刪除原資料。
搜尋與媒體重建搜尋索引並掃描圖片、論文 PDF 與投影片。
個人資料與人名同步引用位置，產生姓名別名並執行一致性檢查。

22. 疑難排解

畫面仍是舊版

Mac 按 Command＋Shift＋R；Windows 按 Ctrl＋Shift＋R。手機可關閉分頁後重開，必要時清除該網站快取。

手機聯絡表單超出邊框

確認最新 assets/script.js 已部署。新版會讓輸入欄位縮入容器，並依可用寬度縮放 Cloudflare Turnstile。

人名連結讀不到目前檔案

新版會等待、重試並破除 content/people.json 快取；若仍失敗會顯示明確錯誤，不會把空資料當成正式資料。

排序看不到項目

確認主要類別或引用屬於目前頁面；PDF 履歷與審查資料還需確認類別已納入。

類別風格不能修改

先移走該類別所有主要項目與引用。

GitHub Actions 失敗

保留本機草稿，查看第一個失敗步驟，不要先清空草稿。

23. 送出前完整檢查

  • 中英文標題、機構與地點均已檢查。
  • 日期格式正確，起訖日期沒有顛倒。
  • 主要類別正確，額外引用沒有重複。
  • 作品作者使用人名連結的標準姓名。
  • PDF、投影片、DOI、arXiv 與網站連結可開啟。
  • 首頁、PDF 履歷與審查資料順序符合預期。
  • 右側預覽沒有意外刪除或大量不明變更。
  • 保留本機草稿直到 GitHub Actions 成功。
最安全的原則：先預覽完整差異，再送出；送出後先看 GitHub Actions，最後才清空草稿。
