1. 日常操作流程

核心原則：Admin 裡的修改先存在目前瀏覽器，不會立刻改動 GitHub 或公開網站。
  1. 在「項目」「新增」「排序」「資料庫」或「網站設定」建立修改。
  2. 到「草稿」和右側預覽確認修改前後差異。
  3. 按「前往 GitHub 送出批次」，建立一張批次 Issue。
  4. 等待 GitHub Actions 完成測試、重建網站並部署。
  5. 確認成功後，再清除已送出的本機草稿。
不要在 Issue 剛建立後立刻清空草稿。建立 Issue 只代表請求已送出，不代表自動流程已成功。

2. 先理解資料結構

頁面→類別→項目
頁面決定網址、導覽列、頁首、語言版本與主色。例如首頁、履歷、論文、學術活動、教學。
類別頁面裡的大區塊。類別決定標題、簡介、顯示風格，以及是否納入 PDF 履歷或審查資料。
項目真正的內容資料，例如一篇論文、一場報告、一段學歷、一筆聯絡資訊。

主要類別與引用位置

每筆項目必須有一個主要類別，也可以被引用到其他相容類別。引用不是複製資料：修改原項目後，所有引用位置會一起更新。

  • 主要類別決定這筆資料的管理歸屬。
  • 引用位置只決定它還要在哪裡顯示。
  • 移除引用不會刪除原項目。
  • 每個顯示位置都有自己的排序。

3. 草稿、正式資料與衝突

狀態意思
正式資料目前 GitHub cms 分支中的內容，也是重新整理 Admin 後載入的基準。
本機草稿目前瀏覽器保存、尚未送出的修改。換瀏覽器或清除網站資料時不會自動跟過去。
批次 JSON送到 GitHub Issue 的實際操作內容，通常只需檢查，不需手動修改。

如果正式資料在你開啟 Admin 後被其他流程改動，後端會比較修改前版本，避免舊草稿直接覆蓋新資料。遇到衝突時，重新載入正式資料後再建立新的草稿。

4. Admin 的主要入口

入口用途
項目搜尋、篩選、查看、編輯或刪除既有頁面、類別與內容。
新增新增頁面、類別、作品、活動、教學、榮譽與一般內容。
草稿查看目前未送出的修改；可返回編輯、預覽或移除單筆草稿。
排序調整頁面中的類別與項目順序，也管理首頁、PDF 履歷、審查資料與個人資料的排列。
7 日垃圾桶查看最近七天已正式套用的操作，建立還原草稿。
中英對照／資料庫管理中英詞條、標籤、人名連結與一致性檢查。
網站設定管理一般設定、聯絡表單、SEO／OG 與流量統計。
通知查看部署、arXiv、正式出版、失效連結與聯絡留言。

右側「預覽與送出」會彙整各模組的草稿；技術資料可展開查看整批 JSON。

5. 使用項目清單

「項目」列出頁面、類別與內容。搜尋會比對名稱、標題、機構、作者與識別碼；篩選只改變目前畫面，不會修改網站。

  • 網站順序：依目前頁面、類別與項目位置排列。
  • 日期排序：方便找最近或最舊的資料，不會改變正式順序。
  • 名稱排序：只用來檢視。
  • 頁面與類別：會顯示所屬頁面、語言版本或顯示風格。
  • 特殊項目：編輯「個人資料」會前往個人資料表單；編輯「PDF 履歷」會前往其排序畫面。
刪除類別前：必須先移走該類別中的主要項目與引用。頁面也不能當成普通內容直接刪除。

6. 新增與編輯的共同規則

中英文欄位

中英文分開保存。啟用自動填寫時，系統會先查人名連結與中英對照資料庫；找不到匹配時，不應把自動結果當作正式翻譯，請自行檢查。

日期

  • 可使用日期選擇器或輸入標準日期。
  • 單日活動可讓開始日期與結束日期相同。
  • 有起訖日期時，請確認結束日期沒有早於開始日期。

連結與檔案

  • 外部連結使用完整 https:// 網址。
  • 站內檔案使用 repository 根目錄相對路徑，例如 files/slides/example.pdf。
  • 論文可分別保存 arXiv、PDF、DOI、期刊頁與程式碼連結。

儲存後發生什麼

按下表單的儲存按鈕只會建立或更新本機草稿。右側預覽會顯示修改前後；正式網站要等批次送出與 GitHub Actions 成功後才更新。

7. 各資料類型怎麼選

作品／論文論文、預印本、綜述與其他作品。包含作者、期刊狀態及多種連結。
活動新增入口先選「活動」，再選學術會議、學術報告、學術訪問或學術籌辦。
教學課號、課名、學期、教學身分、課程頁與講義。
榮譽獎項、獎助、錄取與其他榮譽紀錄。
一般內容學歷、任職、研究興趣、技能、聯絡資訊與自訂內容。
頁面／類別建立新的公開頁面或頁面中的內容區塊，不是一般內容項目。

四種活動的差別

學術會議參加會議、工作坊或研究集會；可記錄身分、日期與地點。
學術報告有報告題目、活動名稱、機構與投影片的演講紀錄。
學術訪問研究訪問、訪問機構、地點、資助與說明。
學術籌辦主辦、協辦或召集會議、研討會、讀書會等活動。

同一場會議的「參加紀錄」與「籌辦紀錄」是不同資料意義；需要同時出現時，應分別建立兩筆。

8. 一般內容的六種顯示風格

顯示風格只描述版面，不限制內容用途。新增與編輯一般內容時都可以選擇，但目標類別必須使用相容風格。

風格適合內容
標準時間軸一般經歷、職務、活動或有明確時間的紀錄。
雙欄紀錄學歷、任職等需要左右欄呈現日期與內容的紀錄。
標題清單研究方向、主題清單與較短的文字項目。
資訊卡片聯絡方式、重要資訊與適合卡片呈現的內容。
標籤列表語言、技能、關鍵字與短標籤。
精簡時間軸榮譽、獎項與簡短日期紀錄。
類別風格不能修改時：通常是類別中仍有主要項目或引用。先把內容搬到相容類別，再修改或刪除類別。

9. 頁面、類別與引用位置

頁面設定

頁面可設定中英文名稱、頁首文字、主色、語言版本、導覽列顯示及順序。新增頁面後，網址由頁面識別碼產生；不要用兩個頁面共用同一識別碼。

類別設定

類別可設定中英文小標題、大標題、簡介、所在頁面、顯示風格，以及是否出現在網站、PDF 履歷或審查資料。

引用項目

同一筆資料可引用到其他相容類別。修改原資料會同步更新，但各位置的順序彼此獨立。

「納入輸出」與「排序」是兩件事。先讓類別納入 PDF 履歷或審查資料，再到相應排序畫面安排位置。

10. 排序、搬移與重設

在「排序」選擇要管理的頁面或特殊輸出後，可調整類別順序、類別內項目順序及項目歸屬。

  • 上下按鈕改變目前顯示位置。
  • 「搬移」只列出顯示風格相容、能安全接收該項目的類別。
  • 跨頁搬移後，項目會跟著目標類別出現在另一頁。
  • 快速排序可依日期或名稱調整，但作品與教學仍保留既有分組。
  • 類別的「重設」只撤銷該排序區內尚未送出的變更，不會回復其他表單欄位。

排序修改也會形成草稿。離開排序頁前確認畫面已顯示「有未送出變更」，並到草稿預覽檢查。

11. 首頁內容怎麼管理

首頁上方基本資料

從「項目」編輯首頁，可管理姓名、身分、說明文字及首頁按鈕。照片、精選論文、近期活動和聯絡區不是在同一表單修改。

精選論文與近期活動

在「排序」選擇首頁後，直接管理兩個首頁區塊：

精選論文可選最新 N 篇、最舊 N 篇或手動挑選。自動模式先決定入選項目，再套用管理者調整的相對順序。
近期活動可選最近 N 筆、日期最遠 N 筆或手動挑選。已結束的活動不再顯示，但原始資料不會被刪除。

首頁設定只控制首頁呈現，不會修改論文或活動本身。

12. 個人資料、PDF 履歷與審查資料

個人資料

可集中管理姓名、所屬單位、職位、學校信箱、個人信箱、網站、ORCID、地址、辦公室與語言。其他頁面使用引用，不需重複建立相同資料。

PDF 履歷

  • 只有勾選納入 PDF 履歷的類別才會輸出。
  • 中英文 PDF 共用類別與項目順序，但顯示各自語言內容。
  • 作品依類別分組並各自編號；教學可依機構分組。
  • 尚未結束的活動不列入已完成活動紀錄。
  • 空類別不輸出。

審查資料

  • 先讓類別納入審查資料，再到「排序 → 審查資料」安排順序。
  • 個人資料區塊顯示姓名、所屬單位與職位；聯絡區不重複顯示。
  • 螢幕與列印版使用不同排版；列印時會隱藏導覽列、頁尾及操作按鈕。

13. 中英對照資料庫

中英對照採完整欄位精確比對，不是翻譯模型，也不做模糊關鍵字推測。

  • 同一英文詞條不能同時對應兩個不同中文詞條，反之亦然。
  • 標籤可新增、改名、合併、刪除與排序。
  • 多標籤篩選表示必須同時符合所選標籤。
  • 安全合併會保留匯入檔未列出的既有資料。
  • 完整取代前必須仔細檢查刪除量。
  • 資料庫修改仍是本機草稿，需與其他修改一起送出。

14. 人名連結資料庫

每位人物可保存英文標準姓名、中文標準姓名、學術網頁與其他拼法。其他拼法只用於搜尋與匹配，不會取代網站正式顯示名稱。

姓名類型常見自動別名
華人羅馬字姓名連字號、空格、合併寫法、姓前名後與逗號格式。
外國姓名中間名、首字母縮寫、姓名順序與逗號格式。
  • 作者欄出現候選時，必須點選候選才會套用標準姓名與連結。
  • 姓名一致性檢查可找出既有作品中可替換的作者寫法。
  • 直接從其他模組開啟人物時，系統會等待正式人名檔載入；若失敗會顯示錯誤，而不是把空資料當成正式檔案。

15. 網站設定

一般設定個人資料、網站封面、導覽列、頁尾、404 頁面與公開資訊。
聯絡表單Web3Forms Email-Only 或 Cloudflare Worker 橋接模式，以及 Cloudflare Turnstile。
SEO／OG基準網址、網站名稱、分享圖片、各頁標題與描述。
流量統計Cloudflare Web Analytics 或 Google Analytics 4。

設定修改與內容修改一樣先存在本機草稿。涉及金鑰或服務設定時，只填公開端允許使用的值，不要把私密金鑰直接寫進公開 repository。

16. 通知中心

  • 部署：查看最近自動流程是否成功。
  • arXiv：把候選論文加入草稿、忽略、加星號或標記已讀。
  • 正式出版：把預印本更新為期刊論文草稿。
  • 失效連結：跳到對應內容或設定修正。
  • 聯絡留言：開啟收件匣並標記已處理。

通知的「已讀」「忽略」與「已處理」狀態若要跨裝置保留，也需經過正式送出流程。

17. 使用七日還原

「7 日垃圾桶」保存最近七天已正式套用的操作。它不是直接復原，而是建立一筆新的還原草稿。

  1. 搜尋並展開要還原的操作。
  2. 確認還原預覽的方向正確。
  3. 把該操作加入本機還原草稿。
  4. 與其他草稿一起送出批次。

如果目標資料在原操作後又被修改，後端會阻止舊版本覆蓋新內容。此時應手動編輯目前資料，而不是強行還原。

18. 送出批次與部署

  1. 在右側預覽確認沒有意外刪除、錯誤搬移或異常大量變更。
  2. 按「前往 GitHub 送出批次」。
  3. 建立標題以 [Website: Batch] 開頭的 Issue。
  4. GitHub Actions 會驗證資料、執行測試、生成網站、搜尋索引、PDF 履歷與審查資料。
  5. 成功後會提交產生結果、關閉 Issue 並部署 GitHub Pages。
  6. 最後回到 Admin 清除已成功送出的本機草稿。
Actions 失敗時：先保留草稿，查看第一個失敗步驟。不要因為後面顯示部署未執行，就忽略前面真正的測試錯誤。

19. 疑難排解

畫面仍是舊版

Mac 按 Command＋Shift＋R；Windows 按 Ctrl＋Shift＋R。手機可關閉分頁後重開，必要時清除該網站的快取。

手機聯絡表單或 Turnstile 超出邊框

確認最新 assets/script.js 已部署，並重新整理快取。新版會限制輸入欄位寬度並依容器縮放 Turnstile。

人名連結打不開或讀不到目前檔案

先重新整理 Admin。新版會等待並重試載入 content/people.json；仍失敗時應顯示明確錯誤。不要在空白人名清單上按儲存或完整取代。

排序看不到某筆項目

確認項目的主要類別或引用位置屬於目前選取的頁面。PDF 履歷與審查資料還要確認類別已勾選納入。

無法修改類別風格

類別中仍有主要項目或引用。先搬走全部內容，再修改或刪除類別。

GitHub Actions 測試失敗

看 traceback 最後一段，找到第一個 FAIL 或 ERROR。測試應檢查功能與資料結構，不應綁死可自由修改的手冊文案。

20. 送出前檢查表

  • 中英文標題、機構、地點與姓名已檢查。
  • 日期格式正確，起訖日期沒有顛倒。
  • 主要類別正確，額外引用沒有重複。
  • 一般內容的顯示風格與目標類別相容。
  • 作品作者已使用人名資料庫的標準姓名。
  • PDF、投影片、DOI、arXiv 與網站連結可以開啟。
  • 首頁模式、數量與順序符合預期。
  • PDF 履歷與審查資料的納入設定及排序都已檢查。
  • 右側預覽沒有意外刪除或大量不明變更。
  • 保留本機草稿直到 GitHub Actions 成功。
最安全的做法：先預覽完整差異，再送出；送出後先看 Actions，成功後才清草稿。
