Admin 完整使用手冊

這份手冊涵蓋新增、編輯、刪除、排序、首頁精選、中英對照、頁面與類別、還原、預覽及 GitHub 送出流程。遇到欄位或流程疑問時，先依對應章節檢查。

1. 核心原則

Admin 內的操作先是本機草稿。只有建立 GitHub Issue 並由自動流程成功套用後，正式網站資料才會改變。
  • 草稿保存在目前瀏覽器；換裝置、無痕視窗或清除網站資料時不會跟著移動。
  • 右側預覽是送出內容的最後檢查點；沒有預覽過的資料不要直接送出。
  • 選填欄位留白時，網站與 CV 不會輸出多餘空行、空標籤或替代文字。
  • Organization（籌辦活動）與 Conference（會議紀錄）完全獨立，不會互相複製或連動。

2. 標準工作流程

  1. 在「項目」找到既有資料並按「編輯」，或到「新增」選擇類型。
  2. 填寫欄位；需要時啟用「中英對照表」與「自動填寫另一語言」。
  3. 先按「在右側預覽」，檢查中英文、日期、連結、分類與空白欄位。
  4. 按「加入新增草稿」或「儲存修改草稿」。
  5. 到「草稿」逐筆檢查；需要時回到編輯器修改或移除單筆草稿。
  6. 確認右側總預覽後，按「前往 GitHub 送出批次」。
  7. 確認 GitHub Issue 確實建立且自動流程完成，再回 Admin 按「已建立 GitHub Issue：清空本機草稿」。

3. 項目、新增與編輯

項目

可用搜尋、項目類型及檢視排序縮小範圍。「網站順序」反映目前正式資料加上本機草稿後的結果；其他排序只影響 Admin 檢視，不會修改網站。

新增

類型順序為：頁面、類別、作品、學術會議／訪問、學術報告、學術活動、教學、一般內容。選擇「學術會議／訪問」後，再選實際資料種類，系統會開啟對應表單；兩種資料仍分開保存。榮譽與研究興趣、學歷、聯絡資訊、個人資訊共用「一般內容」入口，再依所選類別保存為正確類型。日期型項目預設今天；結束日期未填時，系統會使用開始日期。

編輯與刪除

編輯會保留未修改欄位。刪除只會加入刪除草稿，送出前仍可在「草稿」移除。若正式刪除後想恢復，使用「還原」。頁面目前採安全保護，需先處理其中類別後才可移除。

4. 欄位、小標註與自動填寫

功能行為不會做的事
套用中英對照表以整個欄位精確查找另一語言不做部分詞、模糊或 AI 翻譯
自動填寫另一語言離開欄位時補上空白或仍為系統產生的另一側不覆蓋已手動修改的內容
學期規則例如 Fall 2026 與 2026 秋 可互補不猜測不符合格式的文字
日期接受 YYYY-MM-DD，也可用日曆按鈕不接受無法判斷的日期文字
選填留白即不輸出不自動補「無」或空標記

每個表單欄位下方的小標註是該欄位的即時規則；若與本手冊的概述相比更具體，以表單的小標註為準。

5. 各項目類型注意事項

學術會議

「一般參與者」不顯示身分；講者、主辦人、協辦人或自訂身分會沿用原本的標題後方樣式。會議資料不會建立籌辦活動。

學術報告

投影片網址為選填。CV 會把 slides 連結放在標題下一行，避免長標題與連結互相擠壓。

學術訪問

城市、國家、說明、資助機構與資助計畫可分開填寫。啟用「自動生成說明」後，資助資料會產生對應中英文；生成結果不加句點。手動說明仍可保留在地點與資助資訊之間。

學術活動

活動類型與籌辦身分分開設定；這是獨立項目，只出現在所選 Organization 類別。

作品

  • 「自動判定」會把有 DOI、期刊頁或正式刊登資訊的項目歸入 Journal Articles，否則歸入 Preprints。
  • 填 arXiv 編號可自動建立 arXiv 網址；填標準 arXiv 網址也可回填編號。
  • 作者編輯器可逐人輸入中英文姓名，並標記本人；系統會產生正確作者順序與本人強調格式。
  • PDF、arXiv、DOI、Journal、Code 連結在 CV 中會另起一行。

教學

課號與課名分開輸入，儲存時合併。機構決定 Teaching Experience 下方的子標題。可選擇「課程資訊頁面」，網站會顯示 Course Information／課程資訊按鈕；也可填講義的中英文標題與連結。頁面選「無」且講義欄位留白時，顯示與舊版完全相同。

一般內容

榮譽、研究興趣、學歷、聯絡資訊、個人資訊及原本的一般項目統一從「一般內容」進入新增表單。先在「內容格式」明確選擇一般項目、學歷時間軸、研究興趣清單、聯絡卡片、個人資訊列表或榮譽時間軸；「所屬類別」接著只會顯示使用該格式的類別。格式不同時網站排版也不同，例如學歷與榮譽使用時間軸、研究興趣使用清單、聯絡資訊使用卡片。

日期、機構、說明與連結都是彈性欄位。「顯示日期」保留中英文手填，因此可只填年份、學期或自訂期間；CV 日期欄固定為單行。修改既有項目時格式固定，避免誤改後遺失欄位。

在「排序」中，每個項目的「移到其他類別」只會列出使用相同內容格式的類別，所以預印本與期刊論文可以互相搬移；格式不同的類別不會出現在選單中，以免欄位或排版遺失。

6. 草稿與預覽

  • 按草稿的「預覽」可查看單筆修改前後。
  • 新增與修改草稿可再次「編輯」；儲存後會更新原草稿，不會重複新增一筆。
  • 首頁精選草稿也列在這裡，可修改、預覽或單獨移除。
  • 「移除」只移除該筆草稿；「清空內容草稿」會移除內容、排序、首頁精選與還原草稿，但不等同刪除正式網站資料。
  • 右側「技術資料：批次 JSON」供除錯或大型批次貼上使用，平常不需手動修改。

7. 排序、頁面與類別

排序

可用日期或名稱快速排序，再用上下箭頭微調。論文保留作品類別、教學保留機構，只在各自群組內排序。另有統一頁面排序可調整頁面內類別、類別內項目及 PDF 履歷類別順序。

頁面與類別

  • 頁面與類別都在「新增」中建立，也可在「項目」搜尋、篩選及編輯，不再占用獨立分頁。
  • 新增頁面可選雙語、僅中文或僅英文，並套用現有內頁模板。單語頁面不顯示語言切換按鈕；僅中文頁面需填英文網址代稱。
  • 頁面可編輯導覽名稱、頁首小字、主標題、說明與主色；只有實際使用的語言欄位必須完整。語言版本建立後固定，避免留下失效網址。
  • 類別可編輯所屬頁面、小字、主標題、說明，以及是否顯示於網站或 PDF 履歷。
  • 「項目」清單的標籤會明確標出項目類型、所在頁面與所在類別；頁面項目則顯示語言版本。
  • 類別移到另一頁時，其項目會跟著移動。
  • 刪除含有項目的類別時，必須先選擇同類型的接收類別；沒有相容類別時系統會阻止刪除。
  • Publication 與 Teaching 在 CV 中使用頁面主標題，再依作品類型或機構顯示子標題；空群組不顯示。

8. 首頁精選與近期活動

這組功能位於「排序」下方的「首頁精選與近期活動」摺疊區，不再使用獨立分頁。

這裡只控制首頁雙欄。論文與活動原始資料仍保留在「項目」及各自的完整頁面，不會因為從首頁移除而被刪除。

精選論文

模式首頁結果適合情況
固定最新 N 篇依論文日期由新到舊取 N 篇希望首頁自動跟著新論文更新
固定最舊 N 篇依論文日期由舊到新取 N 篇要固定突出早期代表作
手動選擇與排序只顯示已加入的論文，並依手動順序排列要自行策展，不受日期影響

自動模式的 N 可設為 1–50。手動模式按「加入」選取論文，再用「上移／下移」調整順序；按「移除」只會移出首頁，不會刪除論文。

近期活動

  • 「最近即將開始的 N 筆」依開始日期由近到遠自動選取；「日期最遠的 N 筆」方向相反。
  • 手動模式可加入、移除與排序尚未結束的活動。
  • 無論使用哪種模式，結束日期早於網站產生日期的活動都不顯示，避免過期活動留在 Upcoming。
  • 要修改活動的標題、日期、地點、身分或連結，回「項目」編輯原始活動；此頁只控制首頁選取與順序。

草稿、預覽與還原

每次變更會先保存在目前瀏覽器，並列入「草稿」統一管理。系統只比較目前模式真正會使用的設定；例如自動選最新 N 篇時，不會因未使用的手動清單不同而誤判為修改。右側只列出實際有變更的區塊：只改精選論文時不會重複顯示未變動的近期活動，反之亦然。正式套用後，這筆首頁設定會出現在「還原」，七天內可預覽並還原。

9. 中英對照表

對照表用於固定譯名，例如機構、人名、城市、課程與數學術語。它只在「整個欄位」完全相符時補值，避免未經確認就改寫正式名稱。

  • 一個詞條可有多個標籤；選多個標籤時只顯示全部符合的詞條。
  • 標籤可新增、改名、合併、刪除及排序；刪除前需確認詞條歸屬。
  • 稽核區列出與正式內容不一致的精確匹配，可逐筆或批次套用為草稿。
  • 匯入 JSON 會先分析與顯示差異；「套用為草稿」後仍需走一般 GitHub 送出流程。
  • 遠端對照表若已更新，舊本機草稿會另存備份，不會自動覆蓋新資料。
術語慣例：q-shuffle 對應 q-洗牌，v-adic 對應 v-進。數學變數在網站與 CV 會使用斜體／數學格式。

10. 還原

最近 7 天的新增、修改、刪除、排序與其他支援操作可先預覽，再加入「還原」草稿。還原不是立刻生效，仍要送出 GitHub 批次。

  • 若同一項目在該操作之後又被修改，後端會阻止舊資料覆蓋新資料。
  • 過期紀錄不再顯示或允許還原；歷史檔的實體清理由後續批次一併處理。
  • 送出前請在右側確認「還原」後的內容，而不是只看操作名稱。

11. 送出 GitHub

小型批次會直接開啟已預填內容的 GitHub Issue。資料較大時，Admin 會複製壓縮或精簡後的單一文字內容，再開啟批次表單；只需貼入唯一欄位。

  1. 檢查右側變更數量、每筆前後內容及錯誤提示。
  2. 按「前往 GitHub 送出批次」。若瀏覽器阻擋新視窗，允許此站開啟彈出視窗後重試。
  3. 在 GitHub 建立 Issue，等待自動流程留言完成或出現成功標籤。
  4. 回 Admin 按「已建立 GitHub Issue：清空本機草稿」。這只清除本機草稿，不代表部署成功。
  5. 到正式網站與 CV 再檢查一次。

12. 網站與 CV 顯示規則

  • 網站依「頁面與類別」設定顯示；首頁保留 Selected Publications／Upcoming 雙欄與所有論文、所有活動連結。
  • CV 的 Publications 主標題固定使用 Publications and Preprints，再顯示 Preprints、Journal Articles、Survey Papers 等非空子群組。
  • CV 的 Teaching 主標題固定使用 Teaching Experience，再依學校或機構顯示非空子群組。
  • 會議、報告、訪問與籌辦活動只有在結束日期已過後才進入 CV；當天仍視為進行中。
  • CV 保留原本的雙欄／三欄排列；學歷日期保持單行，教學課名使用較寬主欄，講者身分維持標題後方的原本樣式。
  • 論文以 (1)、(2) 編號；PDF、arXiv、DOI、Journal 與 slides 等連結另起一行。
  • 空類別、空說明與空連結不輸出。

13. 疑難排解

狀況處理方式
Admin 顯示「讀取資料失敗」重新整理；確認不是直接以本機檔案方式開啟，且網站可讀取 content JSON。
另一語言沒有自動填寫確認兩個開關已啟用、另一側為空白，且對照表有完全相同的整欄詞條。
日期欄變紅改用 YYYY-MM-DD 或日曆按鈕；確認結束日期不早於開始日期。
找不到類別或機構到「新增」選擇「類別」建立相容類別，或在「項目」篩選「類別」後編輯；作品／教學也可在表單選擇既有類別。
首頁沒有顯示手動選取的活動確認活動結束日期尚未過期；Upcoming 不會顯示已結束項目。
送出按鈕沒有開啟 GitHub允許彈出視窗；大型批次先確認剪貼簿已有資料，再手動開啟批次表單。
還原被拒絕該項目可能已被後續操作修改；先檢查最新正式資料，不要強行覆蓋。
內容在網站有、CV 沒有檢查類別是否啟用 PDF 顯示；活動則確認結束日期已過。

14. 送出前完整檢查

  • 中英文名稱、標題、說明與專有名詞正確
  • 日期格式正確，結束日期不早於開始日期
  • 網址可開啟，arXiv／PDF／slides 指向正確檔案
  • 項目類型、頁面、類別、作品類型或教學機構正確
  • Organization 與 Conference 沒有誤建成同一筆
  • 首頁精選模式、N、手動選取與順序符合預期
  • 選填空白沒有產生多餘內容
  • 右側逐筆預覽與總筆數正確
  • GitHub Issue 已建立並由自動流程成功處理
  • 正式中英文網站、首頁雙欄、Admin 與兩份 CV 都已檢查
