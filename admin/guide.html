1. 先理解資料流程

Admin 的修改不會立刻改 GitHub。所有操作先存成目前瀏覽器的本機草稿；建立 GitHub Issue 並由 Actions 成功處理後，才會成為正式資料。
  1. 在「項目」「新增」「排序」「資料庫」或「網站設定」建立修改。
  2. 到「草稿」與右側預覽確認所有變更。
  3. 按「前往 GitHub 送出批次」建立 Issue。
  4. 等待 Issue 被自動關閉、Actions 成功並完成部署。
  5. 回到 Admin，按「已建立 GitHub Issue：清空本機草稿」。

同一批次可以同時包含內容修改、頁面與類別、排序、首頁設定、中英對照、人名連結、個人資料與網站設定。後端會在同一次提交中驗證並套用。

3. 項目清單

項目清單包含三種層級：頁面、類別、內容項目。可使用搜尋、項目類型篩選與檢視排序。

  • 網站順序：按照頁面、類別與項目目前的實際顯示順序。
  • 日期新到舊／舊到新：只改 Admin 查看順序，不會改網站。
  • 名稱：依顯示名稱排序。
  • 頁面標籤：一般項目會顯示主要所在頁面；若有引用，也會顯示所有引用頁面。
特殊編輯跳轉：在項目清單點「個人資料」的編輯，會直接前往「網站設定 → 一般設定 → 個人資料編輯」；點「PDF 履歷」的編輯，會直接前往「排序 → PDF 履歷」。

頁面不能從項目清單直接刪除。一般類別可刪除，但必須先移走或刪除其中所有主要項目與引用。

4. 新增與編輯項目

在「新增」選擇項目類型後填表；在「項目」按編輯會開啟相同表單。修改後先加入草稿，不會直接寫入正式資料。

共通欄位

  • 中英文：兩種語言分開儲存。開啟自動填寫時，只使用中英對照資料庫的精確匹配。
  • 日期：可手動輸入或使用日期選擇器；日期區間會在網站上完整顯示起訖年份。
  • 所屬類別：決定項目的主要管理位置與預設顯示頁面。
  • 額外顯示位置：位於表單最下方，可讓同一筆資料出現在其他類別，不會複製資料。
  • 連結：可使用完整 http／https 網址；網站內 PDF 也可使用 /files/... 根目錄相對路徑。
  • 右側預覽：可先看表格與差異，再加入草稿。
自動填寫不是 AI 翻譯。資料庫沒有完全相同的詞條時，另一語言會保持空白。

5. 各資料類型

作品／論文題目、作者、期刊或 arXiv、日期、作品類別、PDF、DOI、程式碼、BibTeX／bibitem。作者以逐人欄位管理，可使用人名資料庫候選。
學術會議會議名稱、角色、日期、城市、國家與說明。角色可為參與者、講者、主辦人、協辦人或其他。
學術訪問訪問機構、日期、城市、國家、資助與說明；可由地點欄位產生中英文描述。
學術報告報告題目、活動、日期、地點與 Slides；會以講者身分呈現在相關活動資料中。
學術籌辦會議、工作坊、研討會或讀書會；可設定主辦、協辦或召集等身分。
教學機構、身分、課號、課名、學期與課程資訊頁。網站和 PDF 履歷可依機構與身分分組。
榮譽以精簡時間軸呈現，適合獎項、獎助與榮譽紀錄。
一般內容用途不受限制，由顯示風格決定網站版面；可放學歷、任職、研究方向、技能、聯絡資訊等。

活動新增入口

「學術會議／訪問」會先顯示二選一畫面；學術報告與學術籌辦有獨立入口。選錯時可返回類型選擇，不需要重新整理。

7. 頁面與類別

頁面

公開頁面可設定中英文名稱、頁首小標、大標、簡介、主色、語言版本、導覽列顯示與順序。中英文路徑由系統依頁面設定管理。

特殊虛擬頁面

頁面作用公開網站
個人資料集中管理個人資料主項目。不生成 HTML，不出現在導覽列。
PDF 履歷管理 PDF 履歷的類別與順序。不生成 HTML；輸出為中英文 PDF。

類別

類別決定頁面中的區塊標題與排版。可設定左上小標、主標、簡介、顯示風格、是否顯示在公開網站、是否放入 PDF 履歷，以及是否放進審查資料。

PDF 履歷與審查資料的「納入」和「排序」是兩件事：先在類別編輯中勾選，再到排序頁決定順序。

8. 主要類別與引用位置

每筆項目只有一個主要類別，但可以有多個額外顯示位置。

一份資料→主要類別＋其他類別引用
  • 修改主資料一次，所有引用位置同步更新。
  • 每個引用位置有獨立順序。
  • 刪除引用只移除那個顯示位置，不會刪除主資料。
  • 移動主要類別不會自動刪除其他引用。
  • 表單中的引用位置統一放在最下面；先從下拉選單選類別，再按「新增引用位置」。

項目清單會用多個頁面標籤顯示主要頁面與所有引用頁面，方便確認同一筆資料出現在哪裡。

9. 個人資料編輯

入口位於：

網站設定→一般設定→第一個按鈕「個人資料編輯」

可集中管理姓名、Affiliation、Position、學校信箱、個人信箱、網站、ORCID、地址、辦公室與語言。

  • Name、Affiliation、Position 會用一致格式出現在 Dossier Profile。
  • Contact 不再重複顯示 Affiliation。
  • 個人資料項目主要歸在「個人資料」特殊頁面。
  • 首頁 Contact、PDF 履歷與其他頁面使用引用。
  • 在項目清單編輯任何受管理的個人資料項目，也會跳回此表單。

10. 排序系統

在「排序」選擇目標頁面或特殊輸出。上方調整類別順序，下方調整各類別中的主要項目與引用順序。

  • 一般頁面：調整網站區塊和內容順序。
  • 個人資料：調整個人資料主項目的管理順序。
  • PDF 履歷：調整 PDF 類別與類別內引用順序。
  • 審查資料：調整 Dossier 類別與項目順序。

快速排序可依日期新到舊、舊到新或名稱排列；作品與教學會保留原本分組，只在各組內排序。套用後仍可用上下箭頭微調。

在一般頁面排序中，可把主要項目移到相容類別；引用項目則可從該顯示位置移除。

11. 首頁精選論文與近期活動

首頁的兩個特殊區塊使用專用設定，不應以一般類別排序取代。

區塊模式
精選論文固定最新 N 篇、固定最舊 N 篇、手動選擇與排序。
近期活動最近即將開始的 N 筆、日期最遠的 N 筆、手動選擇與排序。

手動模式可加入、移除與上下移動。近期活動只列出尚未結束的活動；活動過期後會自動從首頁隱藏，但原始活動紀錄仍保留。

12. PDF 履歷

PDF 履歷是特殊虛擬頁面。類別需先設定「放進 PDF 履歷」，才會出現在 PDF 排序中。

  • 中英文 PDF 共用同一組類別與項目順序。
  • 類別名稱與內容使用各自語言欄位。
  • Personal Information 位於 PDF 履歷特殊頁面，內容引用個人資料主項目。
  • 作品分組各自編號；Preprints、Journal Articles、Survey Papers 可獨立顯示。
  • Teaching 可依機構與身分整理。
  • 空類別不會輸出。

在項目清單點「PDF 履歷」編輯會直接跳到 PDF 履歷排序，不會開啟一般頁面表單。

13. 審查資料（Academic Dossier）

審查資料是中英文公開檔案頁，但預設不放入導覽列。類別需勾選「放進審查資料」，再到「排序 → 審查資料」安排順序。

  • Profile 固定顯示 Name、Affiliation、Position。
  • Contact 排除上述三項，避免重複。
  • 其他內容依勾選的類別與排序自動生成。
  • 可直接列印或另存 PDF。
  • 螢幕使用雙欄 Grid；列印改用可跨頁的雙欄內容流，避免右欄整欄換頁。
  • 列印採 A4、黑白、隱藏導覽列、頁尾與連結按鈕。

14. 中英對照資料庫

中英對照只做完整欄位精確比對，不做模糊翻譯。可管理詞條、標籤、篩選、匯入與匯出。

  • 搜尋：搜尋英文、中文或標籤。
  • 多標籤篩選：採 AND；所選標籤必須全部符合。
  • 標籤管理：新增、改名、合併、刪除與排序。
  • 安全合併匯入：新增或更新，不刪除未列出的資料。
  • 完整取代：匯入檔成為最終資料；使用前務必查看預覽。
  • 匯出：下載目前草稿備份。

匯入後只會成為本機草稿，仍需走一般 GitHub 批次送出。

15. 人名連結資料庫

人名資料庫管理英文姓名、中文姓名、學術網頁與其他拼法。資料的載入、草稿與送出方式和中英對照相同。

自動產生其他拼法

輸入姓名後，系統會自動把常見變體加入「其他拼法」。這些別名只供搜尋、作者候選與精確比對，不會改變論文或網站實際顯示的姓名。

姓名類型自動處理
華人羅馬字姓名名字有／無連字號、名字拆空格或合併、姓前名後、名在前姓在後、逗號格式。
外國姓名名字與中間名縮寫、只保留第一名與姓、保留或省略中間名、姓與名對調、逗號格式。

仍可手動補充其他特殊拼法。第一次開啟人名連結時，若既有人名缺少自動變體，系統會把補上的別名列為人名草稿；預覽並送出一次後，之後便不會重複產生相同變更。作者欄位輸入文字時只顯示候選，必須手動點選才會套用中英文標準姓名。

一致性檢查

系統會比對現有論文作者是否符合人名資料庫。可單筆更改、全部更改或忽略；更改會先加入一般內容草稿。

16. 網站設定

一般設定

第一個按鈕是「個人資料編輯」，其後包含封面照片、導覽列、頁尾與 404 頁面。

  • 封面：圖片、備用圖片、替代文字、說明與裁切位置。
  • 導覽列：品牌、Menu 文字、網站搜尋、搜尋提示、Contact 快捷入口。
  • 頁尾：文字、圖標、自訂圖標、連結、是否新分頁、左右或置中對齊、順序。
  • 404：中英文小標、標題、說明、按鈕、導覽列／頁尾、倒數跳轉與配色。

聯絡表單

可啟用或停用表單，設定 Email-only、Web3Forms 或 Worker 模式，以及欄位文字、成功訊息、隱私說明、Turnstile 和頁面配色。

SEO／OG

管理全站基準網址、網站名稱、預設分享圖片，以及每頁 SEO 標題、Meta description、OG 標題、OG 描述與 OG 圖片。OG 留白時沿用 SEO／Meta。

流量統計

可選 Cloudflare Web Analytics 或 Google Analytics 4，填入對應 Token／Measurement ID 並控制是否啟用。

17. 通知中心

頁首「通知」按鈕會顯示未讀數量與最新部署狀態。

  • arXiv 新論文：可加入論文新增草稿、忽略、加星號或標記已讀。
  • 正式出版：可把預印本轉為 Journal Articles 草稿，再人工確認卷期頁碼。
  • 失效連結：直接跳到對應項目或設定修改。
  • 聯絡留言：開啟 Email 收件匣並標記已處理。
  • 部署狀態：顯示成功、進行中或失敗，並可開啟 GitHub Actions Log。

通知的已讀、星號、忽略、刪除與已處理狀態同樣先成為草稿，送出後才永久保存。

18. 草稿、預覽與批次 JSON

「草稿」列出每筆尚未送出的操作，包括新增、修改、刪除、頁面與類別、排序、首頁、個人資料、資料庫、通知與網站設定。

  • 修改草稿：回到對應表單或管理介面。
  • 預覽：查看單筆修改前後差異。
  • 移除：只移除該草稿，不影響正式資料。
  • 清空內容草稿：一次清除目前瀏覽器中的未送出修改，請謹慎使用。

右側總預覽會合併所有操作。技術資料中的 JSON 是實際送到 GitHub Issue 的批次內容，通常不需要手動編輯。

19. GitHub 送出與部署

  1. 確認右側沒有「不能送出」錯誤。
  2. 按「前往 GitHub 送出批次」。
  3. 小型批次會自動預填 Issue；大型批次依畫面指示貼上 JSON。
  4. 建立標題以 [Website: Batch] 開頭的 Issue。
  5. Actions 會執行測試、套用資料、生成網站、Dossier、PDF 履歷、搜尋索引與媒體清單。
  6. Issue 成功後會加標籤並自動關閉，接著部署 GitHub Pages。
不要在 Issue 剛建立時立刻清空草稿。先確認批次 Actions 成功；失敗時本機草稿是重新送出的依據。

同時有其他更新抵達時，workflow 會拉取最新 cms 分支並重新套用，避免直接覆蓋別人的新資料。

20. 還原與最近操作

「還原」保留最近 7 天的操作紀錄，可搜尋、查看 JSON、預覽與建立單筆還原草稿。

  • 還原同樣先加入草稿，必須再次送出。
  • 如果項目在原操作後又被修改，系統會阻止舊版本直接覆蓋新內容。
  • 頁面、類別、首頁與網站設定也會留下歷史差異。

21. 自動產生與同步

功能自動行為
網站頁面依頁面、類別、主要項目與引用生成中英文 HTML。
PDF 履歷依 PDF 類別順序生成中英文 LaTeX 與 PDF。
Dossier依審查資料勾選與排序生成中英文頁面，並套用列印版 CSS。
首頁近期活動過期後自動停止顯示，不刪除原資料。
搜尋重建搜尋索引；訪問描述只組合城市、國家與訪問說明，避免重複。
媒體建議掃描 repository 內圖片、論文 PDF 與 Slides，在相關網址欄位顯示建議。
內頁預取同網域 HTML 連結在滑鼠停留或觸控時預取；慢速網路與省流量模式停用。
個人資料同步 Name、Affiliation、Position、聯絡資訊、SEO 名稱與各引用位置。
人名連結產生常見姓名別名並供作者搜尋與一致性檢查。

22. 疑難排解

畫面仍是舊版

先按 Command＋Shift＋R（Windows：Ctrl＋Shift＋R）強制重新整理。

按鈕沒反應

打開瀏覽器開發者工具 Console 查看第一個紅色錯誤；同時確認最新 Actions 已部署成功。不要反覆按送出。

排序看不到項目

確認項目的主要類別或引用位置屬於目前選擇的頁面；PDF 履歷與審查資料還需確認類別已被納入。

類別風格不能修改

類別只要仍有主要項目或引用就會鎖定。先移走所有內容，再回類別編輯。

人名搜尋找不到變體

進入人名連結頁讓系統產生其他拼法，確認英文姓名格式正確並送出人名草稿。

GitHub Actions 失敗

保留本機草稿，打開通知中心或 Actions 查看第一個失敗步驟。不要先清空草稿或重複建立不同內容的 Issue。

草稿和遠端資料不同

系統會阻止過期快照覆蓋新資料。重新整理 Admin，再把仍需要的修改重新加入草稿。

23. 送出前檢查表

  • 中英文標題、機構與地點都已填寫。
  • 日期格式正確，起訖日期沒有顛倒。
  • 項目主要類別正確，額外引用沒有重複。
  • 作品作者已使用人名資料庫的標準姓名。
  • PDF、Slides、DOI、arXiv 與網站連結可開啟。
  • 首頁精選與近期活動的模式、數量、順序符合預期。
  • PDF 履歷與審查資料都已檢查類別順序及項目順序。
  • 右側預覽沒有意外刪除或大量不明變更。
  • GitHub Issue 建立後保留本機草稿，直到 Actions 成功。
最安全的原則：先在 Admin 預覽完整差異，再送出；送出後先看 Actions，最後才清空本機草稿。
