1. 標準工作流程

Admin 內的操作會先成為目前瀏覽器的本機草稿。建立 GitHub Issue 並由自動流程成功套用後，正式網站資料才會改變。
  1. 在「新增」或「項目」建立、編輯或刪除資料。
  2. 到「排序」調整類別、項目、搬移及首頁精選。
  3. 到「草稿」逐筆檢查，再查看右側總預覽。
  4. 按「前往 GitHub 送出批次」，建立 GitHub Issue。
  5. 等待 Actions 成功完成，再回 Admin 清空已送出的本機草稿。

頁面、類別與項目共用同一份資料；修改可能同時影響網站、中文 PDF 履歷與英文 PDF 履歷。

Admin 頁首使用專用管理圖示，並在「開啟完整使用手冊」右側提供「返回網站」，可直接回到公開首頁。

2. 項目清單

每筆資料上方顯示「項目類型、所在頁面、所在類別」三組提示標籤；頁面項目則顯示語言版本。搜尋、篩選項目類型或切換檢視排序時，標籤與操作按鈕會保持一致。

項目類型篩選中的六種一般內容版面合併成單一「一般內容」選項；篩選只合併查看入口，不會改變項目本身的顯示風格、類別或資料格式。學術會議、學術報告、學術訪問與學術籌辦仍可分別篩選。

「網站順序」反映正式資料加上本機草稿後的位置；日期與名稱排序只改變 Admin 的查看順序，不會修改網站資料。

3. 欄位、小標註與自動填寫

  • 中英文欄位：可分別輸入；開啟自動填寫另一語言時，只會使用翻譯字典中已有的對應，不會臆測翻譯。
  • 小標註：表單欄位下方的提示會說明資料用途、日期格式、是否會出現在網站或履歷。
  • 日期：可使用日期選擇器或手動輸入；沒有結束日期時，單日項目會以開始日期處理。
  • 地點與機構：優先選用字典中的標準名稱，避免中英文頁出現不同拼法。
  • 連結：PDF、Slides、arXiv、ORCID 等會依項目類型顯示成圓角按鈕。
  • 自動產生：訪問等表單的描述產生按鈕優先於一般字典自動填寫。
自動填寫不是機器翻譯。字典沒有對應時，另一語言會保持空白，請自行補上或先到翻譯字典新增對應。

網址欄位：一般連結可使用 http:// 或 https://；電子郵件連結可使用 mailto:name@example.com。

新增活動

「新增項目類型」中的入口叫做「活動」。選擇後可再選擇四種資料：學術會議、學術報告、學術訪問、學術籌辦。

進入四種活動表單後，上方都有「← 返回活動類型」按鈕；若選錯種類，可直接返回四選一畫面，不必切換分頁或重新整理。

「新增」頁只合併入口；「項目」頁的項目類型篩選仍分成四個獨立選項：學術會議、學術報告、學術訪問、學術籌辦，方便只查看其中一類。

4. 一般內容與六種顯示風格

新增和編輯一般內容時，六張版面縮圖本身就是顯示風格按鈕；直接點選卡片即可切換，不需要再操作額外下拉選單。選中的卡片會顯示勾選與強調邊框，標題列也會顯示目前風格。整個區塊仍保留左側收合箭頭，需要節省空間時可縮起來。

選擇後，「所屬類別」只列出能接受該風格的類別；若目前沒有相容類別，儲存按鈕會停用。右側修改預覽會另外列出「修改前風格 → 修改後風格」及所屬類別，不會只顯示文字欄位。

5. 排序、頁面與類別

統一排序

  • 選擇頁面後，可調整類別順序與類別內項目順序。
  • 每個項目都有「搬移」選單，列出所有使用相同格式、可安全接收的類別。
  • 搬移可以跨頁面；項目會跟隨目標類別。
  • 沒有相容類別時，選單仍保留，但呈灰色停用。
  • PDF 履歷檢視只調整履歷類別順序，因此項目搬移選單會停用。
  • 每個排序類別右上角都有「重設」。它只還原該類別的類別位置、項目順序與搬移結果，不會撤銷類別標題、簡介等欄位修改。
  • 長標題會在左側內容欄內換行；上下箭頭與「搬移」選單固定保留在右側同一列，不會因標題過長被擠到下一行。

頁面與類別

頁面與類別從「新增」建立，也會出現在「項目」清單。頁面可選雙語、僅中文或僅英文；類別可編輯中英文標題、簡介、所在頁面，以及網站／PDF 顯示狀態。

類別表單中的用途說明會以一般小字顯示，不會使用佔版面的大型提示框。類別的顯示風格建立後固定；需要另一種排版時，新增對應風格的類別，再透過項目編輯或排序中的「搬移」轉移項目。

PDF 履歷的主標題與子標題

PDF 履歷的主區段使用較粗的完整橫線；作品類別（例如 Preprints、Journal Articles）與教學機構（例如 National Tsing Hua University）使用較小標題與較淡的右側橫線。橫線使用可在一般段落中穩定顯示的水平填滿線，而不是只在 section 標題環境有效的命令。這是共用的子標題樣式，日後新增作品類別或其他教學學校時會自動沿用。

6. 首頁精選與近期活動

在「排序」選擇「首頁」後，「精選論文」與「近期活動」會直接在原本的兩個首頁類別卡中顯示完整的選取與排序介面，不再出現空類別。標題、類別操作、項目列與按鈕沿用其他排序類別的視覺風格。

  • 精選論文：可選最新 N 篇、最舊 N 篇或手動選擇。
  • 近期活動：可選最近 N 筆、日期最遠 N 筆或手動選擇。
  • 自動模式：系統負責決定入選的 N 筆；入選後仍可用「上移／下移」調整首頁顯示順序。之後有新資料進入前 N 筆時，仍會自動更新候選集合，已保留的項目則沿用手動相對順序。
  • 手動模式：可自行加入、移除並排列項目。

操作說明以欄位下方的小字呈現；每個首頁區塊右上角以小標籤顯示「目前無變更」或「有未送出變更」。精選論文與近期活動各自都有「重設」，只還原該區塊。

系統以實際顯示模式、N 值與最終順序判斷是否有變更；若調整後完整改回原狀，狀態會自動回到「目前無變更」，不會因內部暫存順序留下假草稿。變更會先存為本機草稿，並在「草稿」分頁提供修改、預覽與重設。

7. 草稿與預覽

  • 新增、修改、刪除、頁面／類別、排序、搬移、首頁設定與還原都會列入草稿。
  • 頁面、類別與項目排序會在「草稿」中顯示獨立管理列，可回到排序修改、查看預覽或按「重設」放棄這組變更。
  • 首頁精選與近期活動也有獨立草稿管理列。
  • 按「預覽」查看單筆修改前後；新增與修改草稿可再次編輯。開啟的右側預覽右上角有與其他操作一致的「關閉」按鈕，只收起目前預覽，不會刪除草稿。
  • 右側預覽採一致的卡片與修改前／修改後樣式。頁面和類別會逐欄列出實際變更，例如中英文標題、簡介、所在頁面、顯示狀態與順序，不再只顯示概略資訊。
  • 「清空內容草稿」會清除內容、排序、首頁精選與還原草稿，但不會修改正式網站，也不會清除中英對照表草稿。

8. GitHub 送出

  1. 檢查草稿與右側總預覽。
  2. 按「前往 GitHub 送出批次」。
  3. 在 GitHub 確認 Issue 內容完整並建立 Issue。
  4. 確認對應的 GitHub Actions 成功完成。
  5. 回到 Admin 按「已建立 GitHub Issue：清空本機草稿」。
不要在 Actions 尚未完成前清空草稿。若流程失敗，保留草稿可讓你修正後重新送出。

9. 送出前完整檢查

  • 中英文標題、機構、地點與說明是否放在正確語言欄位。
  • 日期、年份、開始與結束時間是否正確。
  • 項目所在頁面、類別及顯示風格是否正確。
  • 搬移後的目標類別是否符合預期。
  • 首頁精選與近期活動的數量、模式及手動順序是否正確。
  • PDF、Slides、arXiv 等連結是否完整。
  • 右側總預覽是否沒有意外刪除、重複項目或標題消失。

10. 還原

還原功能會根據網站修改歷史建立一筆新的反向操作草稿，不會直接改寫 GitHub 上的資料。請先預覽還原內容，再和其他草稿一起送出。

  • 還原新增：會建立刪除草稿。
  • 還原刪除：會以歷史資料建立新增草稿。
  • 還原修改、排序、搬移或首頁設定：會恢復成該次修改前的狀態。
  • 若目前資料已再次被修改，請仔細檢查衝突提示和總預覽。

11. 疑難排解

狀況處理
搜尋、篩選或排序後標籤變舊重新整理一次以載入最新版；新版搜尋、項目類型篩選和檢視排序會固定使用同一個項目渲染入口。
搬移選單是灰色目前沒有其他能接受相同格式的類別；先新增相同顯示風格的類別。
首頁精選介面看不到到「排序」並把「選擇頁面」切換為「首頁」；精選論文與近期活動會直接出現在各自類別位置。
首頁順序沒有套用確認已使用「上移／下移」調整，並到「草稿」檢查首頁設定的修改前後順序。
首頁調整後又改回原狀狀態應自動回到「目前無變更」。若仍顯示有變更，先重新整理確認已載入最新版 Admin。
找不到項目排序草稿排序或搬移後到「草稿」查看「頁面／類別／排序」管理列，可修改、預覽或重設整組排序草稿。
活動種類選錯使用表單最上方的「← 返回活動類型」，回到學術會議、學術報告、學術訪問、學術籌辦四選一畫面。
改風格後出現刪除與新增兩筆草稿這是精簡時間軸（榮譽）與其他一般內容資料區之間的安全轉換，屬正常行為。刪除或改回這筆內容草稿時，系統也會還原它自動產生的類別與排序變更。
右側仍留著不需要的預覽按預覽右上角的「關閉」按鈕；這只關閉畫面，不會移除草稿。
GitHub Actions 測試失敗先查看失敗測試名稱與第一個 AssertionError；不要清空草稿，修正後重新送出。
